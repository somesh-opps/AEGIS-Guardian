=========================================================
AEGIS AI Brain - Startup & System Checking Guide
=========================================================

1. STARTING THE BACKEND SERVER
---------------------------------------------------------
Since this is a Python backend built with FastAPI, you need to run it from within the provided virtual environment (`venv`) to ensure it has access to all dependencies.

Run these commands in PowerShell:
    cd "D:\research\hekafalls 2026\aegis-backend"
    .\venv\Scripts\Activate.ps1
    uvicorn main:app --reload --host 0.0.0.0 --port 8000

*The server will start at `http://localhost:8000`. You can exit it at any time by pressing `CTRL + C`.*

2. SYSTEM HEALTH CHECK
---------------------------------------------------------
While the server is running, you can test if it is responding correctly. Open your browser and navigate to:
    👉 http://localhost:8000/health

You should see this JSON response:
    {"status":"ok","service":"AEGIS AI Brain v1.0"}

For an interactive UI of all available API endpoints, visit the Swagger Docs:
    👉 http://localhost:8000/docs


3. RUNNING SYSTEM TESTS
---------------------------------------------------------
The codebase includes scripts to test the data fusion, detection pipelines, and end-to-end functionality (like testing your Gemini API integration).

Open a new PowerShell terminal and run:
    cd "D:\research\hekafalls 2026\aegis-backend"
    .\venv\Scripts\Activate.ps1
    
    # Test the sensor fusion and incident detection pipeline:
    python test_pipeline.py

    # Test the complete end-to-end flow:
    python test_e2e.py


4. CHECKING WEBSOCKET ALERTS
---------------------------------------------------------
The system streams live alerts for incidents (like Fire, Gas Leaks, etc.) via WebSockets. To verify the WebSocket is active, you can write a quick client script or use a tool like Postman.

WebSocket Endpoint: 
    ws://localhost:8000/ws/alerts

*If you connect to it and trigger an incident using the API docs (at /docs), you'll see the alert JSON pushed in real-time.*


5. CHECKING OLLAMA (Local AI Fallback)
---------------------------------------------------------
If the Gemini API fails, the backend falls back to your local Ollama installation (Qwen2.5:0.5b). Ensure Ollama is running in the background.

Test if Ollama is accessible by opening this URL:
    👉 http://localhost:11434/

You should see the text: "Ollama is running".
